# Bounded HTTP/1 keep-alive

Connections still close after one response unless `Server.keep_alive.enabled` is explicitly true. `Keep_Alive_Config.max_requests = 0` selects100; supported counts are1–10000. `idle_timeout = 0` inherits the resolved `Server.timeouts.idle` budget (5seconds by default); explicit idle overrides up to24hours are supported. Negative/out-of-range settings fail before listening, even when persistence is disabled. Existing header/body/response phase budgets and per-request body/header limits continue to apply.

A connection handles one request and fully sends one response before admitting another. Coalesced pipelined bytes are supported, but handlers never run in parallel on the same connection and responses remain ordered. No unbounded request queue is created. A persistent idle interval has no live request arena or active request observation. The next header deadline starts when the next request's first bytes are admitted, separately from its idle wait; neither header/body nor response progress extends a total phase deadline. Idle expiry closes silently rather than fabricating a408 response or completion event.

Reuse is refused for malformed or unconsumed requests, unsupported/ambiguous request framing, interim/upgrade responses, explicit cancellation, drain, request-count exhaustion, client `Connection: close` (case-insensitive comma-separated tokens, including multiple fields), or handler `Response.close_connection = true`. Invalid Connection token lists conservatively close. The last permitted response advertises `Connection: close`; eligible responses advertise `keep-alive`. Header serialization still owns framing headers. The synchronous `send_response` helper keeps its original connection-close behavior; persistence is managed by the asynchronous server state machine.

After the complete response and exactly-once completion hook, unread next-message bytes are copied to an at-most8KiB temporary ordinary worker-stack buffer while the old arena is destroyed. All request fields, headers, captures, body state, output pointers, metadata and deadlines reset before reuse. At most the bounded header-read buffer is carried into the next request; current body limits remain application policy. This is neither a per-connection stack nor a retained large response buffer. The reset helper is explicitly not inlined so its temporary stack space does not inflate the ordinary disabled path.

Each admitted request gets a fresh generated observation ID. Duration measures admission-to-completion; it excludes between-request idle and the wait of a not-yet-admitted pipelined request. Measure client end-to-end latency separately. Received-byte metrics count consumed HTTP request headers/body, not unread next-message lookahead. A partially received malformed request counts its consumed/read bytes. Completion callbacks run once before their request arena is released and may request stop/drain. There is no additional event for idle EOF/timeout/shutdown. Request-specific application borrows remain invalid after completion; applications must not retain the previous request across keep-alive reuse.

Drain atomically prevents next-request admission. A current request already admitted before drain—including a partial body—may finish within the drain deadline. Prefetched but not yet admitted pipeline requests are discarded. Idle tasks are held in a bounded mutex-protected connection list and woken once when drain starts; there is no periodic idle monitor, new I/O owner, thread, or per-connection stack. Idle registrations are removed before callbacks/free. Immediate stop retains its cancellation semantics.

## Compatibility and measured storage

Named/zero `Response` literals and `make_response` keep their existing behavior. `Response` gains a trailing `close_connection` boolean: external positional three-field literals must add `false` or switch to named fields. No positional Response constructions were found in the inspected shared/Mesa consumers. Copies and development reload injection preserve the new field.

On the development build, compared with the batch2 drain/observability/timeouts baseline: `Connection_Task`2056→2080bytes (+24), `Server_Runtime`6040→6080 (+40), and `Response`40→48 (+8). These are struct-layout measurements, not allocator/RSS or throughput claims. Disabled persistence skips idle-list locking and all reset logic, but retains the bounded inline metadata.

## Validation

`tests/keep_alive.py` builds and controls owned loopback fixtures only; normal, `--sanitize address`, and `--sanitize thread` modes are supported. Cases cover sequential/coalesced/fragmented requests, POST/body boundaries, HEAD, arena out-of-band release, count/idle limits, client/server close, malformed next requests, per-request body caps, EOF, timeout, overload recovery, idle/inflight/observer drain, concurrent drain/admission races, unique IDs and exact per-request byte attribution. Focused unit tests cover validation, token policy, framing and idle-list invariants.
