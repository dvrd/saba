# Saba UI delivery roadmap

Saba is being built for Mesa v2’s web UI in the `web/` directory of `bot-mesa`. Use the selected v2 screen, its API and its permission rules to define a product integration test. The generic Saba acceptance fixture below uses a made-up item title to exercise static HTML, reactive counts, keyed DOM identity and recovery after an interrupted save. The v2 Desk opens a historical workbook as read-only. The wallet form is an example of a separate, revision-checked write. [Desk view](https://github.com/gmvkrog-bit/bot-mesa/blob/7bc8044ab02c2daf23bab432c325b39a99d6da7d/web/desk.js#L415) · [Wallet form](https://github.com/gmvkrog-bit/bot-mesa/blob/7bc8044ab02c2daf23bab432c325b39a99d6da7d/web/wallets.js#L196)

The five implementation milestones below have passed their Odin and Chromium acceptance suites in this checkout. The Mesa v2 adoption decision has its own product comparison. ## Design decisions

| Question | Owner and contract |
| --- | --- |
| What runs at build time? | Kessel supplies syntax and source spans. Saba resolves names needed for extraction and emits only markup it can prove safe to extract. A build publishes the routes, HTML and all browser modules as one generation. [Compiler](adr/0003-saba-jsx-compiler-on-kessel.md) · [Template delivery](adr/0004-saba-compile-time-html-no-request-rendering.md) |
| What runs when data changes? | An owning scope activates a binding. A tracked read updates a text node, property, attribute or child range. Forwarded getters retain the dependency. A keyed row keeps its DOM and draft while its record accessor receives fresh data. [Signals and lists](adr/0002-saba-ui-signals-with-incremental-borrowings.md) · [JSX bindings](adr/0007-saba-reactive-props-and-bindings.md) |
| Which response may publish? | A confirmed read belongs to an identity partition, structural resource key, live cache entry and current request generation. A mutation uses an operation ID and a base revision. The application commits the effect and its receipt under a single durable authority. [Async reads and mutations](adr/0006-saba-async-reads-and-mutations.md) |
| Who owns an editor? | Native navigation selects a public page template. A scoped, authorized API read establishes the editable baseline. The editor owns the draft, the server validates and commits it, and a restored editor reconciles outstanding receipts before enabling another save. [Routed edit forms](adr/0008-saba-routed-edit-forms.md) |

The public JSX transform uses Kessel. Pages registered in `Page_Mount.templates` serve generated HTML and attach bindings to its parsed DOM. Existing directory mounts use the append-style entry. Both support parameterized pages and use the same reactive runtime. [Page builder](../src/pages/build.odin) · [JSX transform](../src/jsx/jsx.odin) · [Template attachment](../src/modules/attach.js) · [Legacy entry](../src/modules/page-entry.js)

## Delivery order

- [x] **1. Compile and run one reactive component.** Kessel compiles authored JSX. Chromium verifies that a count forwarded through a spread changes the same text node, each component runs setup once and removing the child ends its subscriptions. [Authored component](../testdata/ui/forwarded.jsx) · [Compiler checks](../tests/internal/jsx_test.odin)
- [x] **2. Deliver compatible templates and durable DOM identity.** A build publishes localized documents and their immutable module graph together. Browser checks cover repeated component instances, rollback after setup or DOM failure, keyed movement, focus and selection. [Template attachment](../testdata/ui_template/driver.js) · [Keyed row fixture](../testdata/ui/keyed.jsx) · [Generation checks](../tests/pages/build_test.odin)
- [x] **3. Make reads and saves race-safe.** Overlapping reads share work and publish only into the subscribing identity and request generation. The synthetic SQLite service tests duplicate delivery, mismatched payloads, competing revisions and restart at three commit boundaries. A real blocked write leaves another HTTP/2 stream usable on the same connection. [Read checks](../testdata/ui/reads.js) · [Store checks](../tests/ui_store/receipt_test.odin) · [HTTP/2 checks](../tests/offload/protocol_progress_test.odin)
- [x] **4. Route and restore the editor.** The generated `/items/[id]` page receives frozen route parameters, establishes an authorized baseline, preserves later field edits through validation and conflicts, and recovers outstanding operations on full reload and persisted Back. Switching identities before Back hides the old draft and skips its receipt lookup. [Authored form](../testdata/ui/item.jsx) · [Navigation and release checks](../tests/ui/browser_test.odin)
- [x] **5. Pass the Saba browser acceptance fixture.** A new build reads a journal created by its predecessor while a real save remains reserved. Removing the submitting row still updates the two surviving filtered views through a receipt lookup. A delayed import loads its own generation while retained, and an expired entry or optional import exposes a working native reload. [Routed fixture](../testdata/ui/history-helper.js) · [Row removal](../testdata/ui/removing-row.jsx) · [Asset retirement](../tests/ui/delivery_test.odin)

### First implementation steps

1. The forwarding fixture began as a failing browser test. It saves the original badge text node, clicks the parent button, removes the child and checks the child read count after another write. [JSX example](../testdata/ui/forwarded.jsx) · [Odin assertions](../tests/ui/browser_test.odin)
2. The public transform preserves source outside JSX and emits live getters and tracked reads. The runtime forwards those getters across the component boundary and disposes the binding with the child. [Compiler](../src/jsx/jsx.odin) · [Runtime](../src/modules/dom.js)
3. The Taskfile stages the working source into a clean tree and installs the project lock in a private Odin root. The distribution test corrupts a digest in a separate lock and checks that Krs rejects it. [Project lock](../.krs/packages.json) · [Distribution checks](../tests/distribution/lock_test.odin)

### Test entry point

Long, fixed-height collections can opt into the buffered window. The compiled editor benchmark runs its three lists both with the window and fully mounted. Both versions read all 1,000 records from the same API. The million-record fixture exercises scrolling, reversing, resizing and seeking with local data. The authored JSX integration pins one dirty focused row as it crosses the mounted boundary, checks its text selection on return, and retires a delayed cursor page when the query changes. The consumer supplies the focus and paging policy. [Windowed editor benchmark](SABA_UI_PERFORMANCE.md#compiled-editor-with-a-sliding-window) · [Editable window fixture](../testdata/ui/windowed.jsx) · [Window contract](adr/0002-saba-ui-signals-with-incremental-borrowings.md#buffered-windows-for-fixed-height-rows) · [Scrollable window walkthrough](features.html#op/buffered-row-window)

Run `task test` with Odin and Krs on PATH. Each run copies the checkout into a temporary directory, then uses `krs install --frozen` with the project lock in a fresh Odin root. In the Krs user config, set `source_directories` to the parent of the tagged local Webtools repositories listed in the lock. For Kessel use the tagged checkout or configure `libs.kessel` with `{"source":"github","target":"dvrd/kessel"}`. For development, `--shared PATH` or `WEBTOOLS_SHARED` explicitly selects an existing collection. The browser suite finds Chrome on macOS and Chromium on PATH, or accepts an executable via `SABA_CHROME`. `task test -- --package ui` runs authored JSX, compiled-template, editor and native navigation tests. `task test -- --package ui_store` exercises real server crashes and competing writes against SQLite. ## Saba browser acceptance fixture

| Exercise | Passing observation |
| --- | --- |
| Pause the entry after requesting a page. Inspect the parsed HTML. Publish B while A's entry and an indirect import are delayed. Repeat after A expires and with a corrupt instance marker. | The heading is in the first body for both users. A attaches to A's targets or stays readable with a working native recovery link. One badge changes without changing its sibling. Failed attachment leaves zero active bindings. |
| Search for `ad`, then `ada`. Keep a second subscriber on `ad`. Complete `ada` first, then release an `ad` success or failure. Separately queue a decoded response, dispose the last subscriber and reacquire the same key before publication. | The second subscriber sees its own outcome. The visible `ada` rows, count, error and pending state remain correct. The queued completion and its cleanup cannot publish into the newly acquired entry. [Search animation](features.html#op/async-search-order) |
| Type into a keyed row, select a substring, then return fresh records with the same IDs, new labels and a new order. Remove the edited row. | The confirmed label changes and the original input, draft, focus and selection survive the move. Removal decrements the forwarded count without another child setup and releases the row exactly once. [Forwarded getter](features.html#op/reactive-forward-prop) |
| Open `/items/42` directly and delay its first read. Edit after it loads, submit, change a validation dependency while the response is pending, then repeat without changing it. Keep focus inside the form for the current rejection. Finally commit a competing edit from a second client before submitting the old revision. | No draft is lost during initial load. Only applicable field errors attach to their inputs. Applicable errors are announced and focus reaches the invalid field. A conflict retains the draft and requires an explicit choice against the current revision. [Validation animation](features.html#op/route-edit-validation) |
| Double-activate Save. Separately send two real requests with the same ID and payload to Odin, then reuse that ID with different input. Interrupt the server before and after commit and restart against the same store. | The UI sends once for the double activation. Duplicate network deliveries produce exactly one effect and one durable terminal outcome. Reusing an ID with different input is rejected. A later receipt cannot regress a newer confirmed revision. |
| Leave with two same-item operations across independent editors. Drop one committed response. Return by full reload and by a verified persisted Back. Repeat after a change of identity and with an expired receipt. | Each operation retains its own reconciliation state. A restored editor waits for its authorized baseline. A pending or expired receipt cannot authorize a blind retry. No old draft, result or error is presented to the new identity. [Recovery animation](features.html#op/async-reconcile-save) |
| Rename a record so it newly matches a live search, then change identity while a revalidation or save completion is queued. | Invalidation reaches the search through its collection family even though the record was absent. The old completion can neither publish into the new partition nor expose the former user's data. |

The browser fixture and transport fixture exercise two different lifetimes. Removing a submitting row must still let a surviving filtered list learn about the commit through receipt reconciliation, with zero writes to the detached row. On one TLS connection, the HTTP/2 fixture pauses a real SQLite save after reservation and completes an unrelated stream and a pending receipt lookup before releasing the writer. [Browser suite](../tests/ui/browser_test.odin) · [HTTP/2 fixture](../tests/offload/protocol_progress_test.odin)

The framework fixture covers signals and JSX, compatible artifact delivery, keyed lists, scoped async state and a routed form. Stores, more control-flow helpers, source maps, lint, optional per-file hashing and a general typed Odin-to-client protocol can follow independently. Production applications choose how long to retain build archives, route generation-specific assets across serving processes and implement their own durable mutation authority. [Deployment behavior](adr/0004-saba-compile-time-html-no-request-rendering.md#running-this-implementation) · [Receipt adapter contract](adr/0006-saba-async-reads-and-mutations.md#recovery-after-a-server-restart)

## Review and implementation handoff

The renderer's performance target is to beat React on each measured interaction. Track cold entry, editing, saving, reordering and scrolling separately. For a windowed comparison, give the compiled Saba and React views the same data, viewport, overscan and update. Record both the time spent changing the DOM and the time until the browser presents the result. [Comparisons against React](SABA_RENDERER_LOSSES.md)

The browser suite exercises deployment during a save, removal of the submitting component, and a render that fails after part of a page or keyed list has prepared. Build B opens A’s journal, observes the reserved receipt, then reads the canonical record after commit. [Activation and deployment](adr/0004-saba-compile-time-html-no-request-rendering.md) · [Durable operations and protocol compatibility](adr/0006-saba-async-reads-and-mutations.md)

Implementation evidence lives in the repository. The JSX suite checks parser spans and emission. Chromium runs the generated JavaScript through Saba’s server. The SQLite fixture kills a child process at controlled storage checkpoints and reopens the same store on restart. [Compiler checks](../tests/internal/jsx_test.odin) · [Browser suite](../tests/ui/browser_test.odin) · [Durable receipt checks](../tests/ui_store/receipt_test.odin)

The compiled editor benchmarks run through the same SQLite-backed workload as the prototype. Across 12 pairs per profile, the median time to edit was 311.8 ms for compiled Saba and 327.3 ms for the prototype on the constrained profile, and 51.6 ms and 25.4 ms on desktop. The constrained median time from save to confirmed rows was 206.1 ms and 199.0 ms respectively. In a separate cold-navigation test with both documents served using identity encoding, generated module preloads saved a median 86.6 ms per pair. Each unconditional startup module reached the origin once in every trial. Run `task bench:compiled-editor -- --trials 12 --profiles desktop,constrained --out /tmp/editor.json` and `task bench:compiled-preload -- /tmp/preload.json --pairs 12 --document-coding identity`. The synthetic item and legacy sheet measurements are separate from the Mesa v2 adoption decision. [Matched editor measurements](SABA_UI_PERFORMANCE.md#generated-jsx-editor-on-the-same-workload) · [Preload method and both controls](../benchmarks/frameworks/compiled-preload/README.md)

## Mesa v2 adoption decision

The browser comparison runs the original Desk shell from Mesa v2 commit `7bc8044` with deterministic Spanish session, catalog and Operations responses. It compares the existing Desk renderer, compiled Saba JSX and production Solid. All three use Mesa’s own loader, view cache and route transitions. [Comparison harness](../benchmarks/frameworks/operations/README.md) · [Browser observations](../benchmarks/frameworks/operations/smoke.json)

Use the live, read-only Operations view at `/books/operaciones` for the product adoption decision. A subsequent deployment trial needs an authenticated test account and representative data. Verify that the browser actually reads `/api/books/operations`. The same Desk can display a historical snapshot. Today a live refresh clears and rebuilds `<main>` when the request starts and again when it settles. This gives the pilot a specific improvement to demonstrate. [Mesa Desk rendering](https://github.com/gmvkrog-bit/bot-mesa/blob/7bc8044ab02c2daf23bab432c325b39a99d6da7d/web/desk.js#L274-L328) · [Live refresh](https://github.com/gmvkrog-bit/bot-mesa/blob/7bc8044ab02c2daf23bab432c325b39a99d6da7d/web/desk.js#L813-L849)

| Risk | What to prove |
| --- | --- |
| The compiler loses a live value across a component boundary. | Start with authored JSX in milestone 1. Change a parent's signal and inspect the same text node in a grandchild reached through a prop spread. It must show the new value with one setup per instance. A sibling taking an explicit snapshot must keep its original value. Dispose the subtree and check that later writes leave its nodes alone. [Forwarding contract](adr/0007-saba-reactive-props-and-bindings.md#forwarding-and-lifetime) |
| The heading appears quickly while the useful rows arrive late. | Verify the first-response language separately on Mesa's login and link pages. On Operations, record navigation to first correct, authorized rows, alongside the start and end of the session check, source selection, module loads and data request. Preserve those prerequisites in each implementation. Test preloading unconditional entry dependencies under throttling and check for duplicate transfers. A user-specific first response would require a separate delivery decision. [Localized documents](adr/0004-saba-compile-time-html-no-request-rendering.md#request-selected-language) · [Desk startup](https://github.com/gmvkrog-bit/bot-mesa/blob/7bc8044ab02c2daf23bab432c325b39a99d6da7d/web/desk.js#L1368-L1414) |
| The wrong response wins, or Back fetches data Mesa already had. | Have two consumers share a read, remove the first, then the last. Reacquire the key and deliver the retired request's success, failure or cleanup while its replacement is pending. Only the new request may settle the new view. Count requests on a same-document revisit separately. Mesa retains ready pages by view. Saba’s standalone read partition evicts the cache entry on last release. If eviction hurts Back, test keeping a subscription in the authenticated Desk shell for the duration of navigation, with teardown on identity change and a measured memory cost. [Read ownership](adr/0006-saba-async-reads-and-mutations.md#reads) · [Mesa read cache](https://github.com/gmvkrog-bit/bot-mesa/blob/7bc8044ab02c2daf23bab432c325b39a99d6da7d/web/books.js#L105-L144) |
| A custom compiler costs more than its benefit. | Run current Desk, compiler-generated Saba and a Solid implementation against identical responses, permissions, cursors, network profiles and interactions. Measure cold entry, refresh, load-more and warm Back separately. Record p95 time to visible results, request counts, transferred bytes, retained memory and keyboard focus. During an update check whether unaffected DOM nodes survive. Record the application-specific work each version needs for rendering and recovery. [Existing comparison and scope](SABA_FRAMEWORK_COMPARISON.md) |

Agree on a minimum worthwhile user-facing improvement and acceptable regressions before timing the pilot. Adopt Saba on this view only if it preserves behavior and demonstrates that gain over the practical alternatives across repeated runs. If the simpler frontend matches it within run-to-run variation, keep that frontend for the view. Evaluate mutation recovery independently on an endpoint with a verified write contract. The framework's interrupted-save fixture remains the place to test a committed write whose response was lost.

A model-level probe of Mesa at `7bc8044` imported the unchanged `web/books.js` with a controlled transport. Two overlapping initial loads made one request. The next page appended its row, and revisiting the ready model issued zero requests. After a forced refresh, the superseded transport delivered a late success in one trial and a late failure in another. Both left the winning row and ready state intact. The subsequent browser smoke found zero Operations requests on same-document Back for all three renderers. Saba and Solid kept the existing first row on load-more and kept the filter and its focus while refresh was pending. All three cleared their rows when the original loader began a forced refresh. The instrumented harness records latency and memory per visit. Establish a meaningful threshold and representative data volume before using repeated measurements to choose the Mesa frontend. [Behavior report and timing command](../benchmarks/frameworks/operations/README.md)

The compiled JSX browser acceptance suite ran in Google Chrome 157.0.8103.80 on macOS. The Operations behavior report records its own pinned Mesa commit, locale and Chromium version.
