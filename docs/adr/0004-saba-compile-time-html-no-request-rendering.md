# Saba renders HTML at compile time, never per request

The compiler emits build-time markup as HTML and emits JavaScript for the parts that depend on runtime state. After applying the route's access policy, the Odin server selects a prebuilt document. Readers of the same page in the same language receive the same HTML within a build. Private data arrives through authorized requests after the browser attaches.

## Considered options

- **Embed a JavaScript engine in the server**: rejected; a native dependency and script execution on every request.
- **Components in Odin with a WebAssembly client**: rejected; it gives up the plain-JavaScript client, the strict content security policy and the build without a bundler, and WebAssembly reaches the DOM only through JavaScript.
- **Compile component templates to Odin**: not taken now; it is the route to revisit if a page ever must show user data before its scripts run, since Kessel can restrict such components to a translatable subset.

## Consequences

A user's data is never in the first response's markup. There is no hydration mode in the runtime.

Parameterized editor routes reuse the selected language's document across record IDs. The browser selects the record from the matched URL and loads its data under the editor’s scope. [Routed edit forms](0008-saba-routed-edit-forms.md)

## What the compiler may put in a document

Extract intrinsic markup, static attributes and escaped text whose value and HTML parsing context the compiler can prove. Follow a component reference only when Saba can resolve its lexical binding and prove the expansion safe. Never run application module initialization, a getter, a tag function or a fetch during extraction. Unknown values stay in the external module. A client-only subtree gets an empty marked range in the document. Its parent and siblings can still be emitted. A static title or heading must be present in the HTTP response before any script runs.

## The document and module belong to one build

The build emits a route table, each page's HTML variants and matching attachment descriptions, its entry, and every framework or application module reachable from that entry. The HTML identifies its generation and page. The entry and every transitive build-controlled import use immutable URLs under the same generation, for example `/__saba/build/<generation>/inbox.js`, where the generation is 32 hexadecimal digits derived from content. Validate the complete artifact set before atomically switching the server's active route table. A build error leaves the previous generation active. Apply the route's document cache policy and keep old generations for a declared deployment grace period. After retirement an old asset URL may return an error. It must never resolve to newer bytes. The same compatibility rule applies to a development rebuild.

A page descriptor chooses one startup mode. Existing pages can keep their empty host and append-style mount. A compiled-template page has its own attachment entry. Native navigation starts from the new document. The generation identity is a digest of everything the generation serves, so it is never reused for different bytes. There is no per-file content hash: every module URL changes with its generation. Applications choose the archive retention described below.

## How the browser attaches

1. The compiler gives each extracted component occurrence an instance boundary and local target identifiers. The manifest records the expected element kind and namespace, attribute target, or ordered range boundaries inside that instance. Repeated components may reuse the same local identifier. Adjacent or initially empty child holes each have distinct markers in the parsed DOM. A guaranteed text binding owns one existing text node, or creates one between its own markers on its first nonempty write.
2. The entry checks generation and page, resolves **every** initial target relative to its instance, then validates unique ownership, types, order and nesting. A structural reader owns the range between its markers. Lookup operates on the browser's parsed tree. Emit valid markup for its context or leave the subtree client-built when parser normalization would change ownership, including table content. [Binding rules](0007-saba-reactive-props-and-bindings.md)
3. Successful preflight opens a disposable root scope for synchronous setup. Queue listeners, user effects and resource starts. Stage initial binding writes until all instance setup succeeds. Commit the bindings before enabling controls and releasing the queued work. If setup fails, revoke that scope, cancel subscriptions, release refs and retain or restore the original template. The served host carries `data-saba-pending` and `aria-busy="true"` rather than `inert`, so its static content stays readable; controls that require JavaScript are disabled in the markup. [Attaching to served HTML](0002-saba-ui-signals-with-incremental-borrowings.md#attaching-to-served-html) The document includes a visible native reload link or equivalent ordinary navigation that works even if the entry never downloads. Hide it after successful activation. Recovery requires a user action and cannot create a reload loop.

### Module resolution and activation boundaries

The public JSX transform preserves neighboring author code. A separate build pass resolves and rewrites module specifiers against the artifact graph, including the injected runtime import, application aliases, root-absolute imports, re-exports and literal dynamic imports. The pilot diagnoses an unresolved build-owned import or computed module URL at its source position. A third-party browser module must be declared as an immutable external URL permitted by the application’s content policy. A mutable external URL cannot stand in for a build-controlled dependency. Use external modules under the existing script policy. Include both a root-absolute runtime import and a delayed literal dynamic import in the deployment test.

Generate the component's browser setup with two explicit placement paths. A template entry binds its extracted positions to existing nodes and constructs only the client-owned ranges. A later dynamic component constructs its own nodes using the runtime. Each mounted instance runs setup once. Attachment must never pass the template root through append-style mount. Keep application setup, module initializers and initial render expressions free of irreversible external writes. Register reads and user effects with the root scope and start them after the initial binding commit. Failure before commit discards staged work and preserves the document. After activation, a later read failure belongs to the resource or editor’s normal error state. Framework rollback covers owned work and DOM changes. Arbitrary external effects cannot be rolled back.

## Acceptance

Capture response bytes and DOM references **before** allowing the entry to execute. Request the same page through two authenticated sessions with scripts blocked. Both bodies contain the actual heading, two repeated badge instances and their initial target markers, with no personal values. Enable the entry, update just the second badge, and verify the same heading, target node and focused control survive. Include empty and adjacent holes. Separately corrupt a marker in the second instance and inject a setup exception after an earlier instance registered cleanup. Queue a read and effect in the earlier instance. In both failure runs the document remains readable, the host keeps `data-saba-pending` and its controls do nothing. Count zero dispatched requests, started user effects or clickable handlers, and verify each registered cleanup ran once.

Serve HTML from generation A, publish B, then release A's delayed entry and a nested import. While A is retained, its document must activate with A alone. If a required startup module has expired, the document stays readable with its native recovery link. If an optional import is requested after activation and A has since retired, report the feature as unavailable and expose the same navigation without applying a partial feature change. Repeat after A is retired, during a failed B build and with a legacy mount page. A clean reload after a successful publish uses B.

The existing test checks “Welcome back.” and “Bienvenido.” in the bytes returned by `/login`, plus the English heading on an authenticated `/link` request. For the Saba pilot, the application declares a finite set of languages, its default and the public copy used at build time. A single-language route needs one document. A localized route emits one per declared language, including `<html lang>`, title, headings and accessible labels. Resolve declared static keys with the application's fallback and escape the result for its HTML context. Mesa's static copy falls back from a missing English entry to Spanish, then to the key. The browser uses the selected document's language and matching generation for dynamic copy. Language-independent modules can be shared across variants. [Mesa catalog lookup](https://github.com/gmvkrog-bit/bot-mesa/blob/7bc8044ab02c2daf23bab432c325b39a99d6da7d/src/api/api.odin#L1728-L1745)

The application owns negotiation. Mesa accepts an unambiguous `mesa.lang=en` or `es` cookie. Otherwise it reads the first `Accept-Language` token, selects English for a case-insensitive `en` prefix and defaults to Spanish. Saba looks up the resulting language in the matched route's variant table from one captured generation. User identities, account data and record IDs stay outside that table. A missing declared variant fails publication. [Mesa language selection](https://github.com/gmvkrog-bit/bot-mesa/blob/7bc8044ab02c2daf23bab432c325b39a99d6da7d/src/api/api.odin#L1680-L1719)

Keep Mesa's document routes on `no-store`, including when a request supplies a validator. A route that allows document revalidation must select the representation before comparing its ETag and vary on all request headers used to select it. A changed language with different HTML must return the new body. Private documents must go through the route's access check for every language.

**Pilot acceptance.** Request `/login` with scripts blocked. Check English from the header, Spanish from a cookie overriding that header, and Spanish with no recognized preference. Check the document language, visible heading and accessible language selector in each response. Activate the page and exercise a dynamic label in the same language. Request `/link` signed out and verify its redirect. Two authorized sessions using the same language must receive identical document bytes containing no account values. Change the cookie to Spanish at the same URL and send a conditional request. Mesa must return the Spanish body with `no-store`. On a route configured for revalidation, sending the English ETag with the Spanish request must return the Spanish body with its own ETag. Withhold one declared locale artifact from a candidate build and verify both languages still come from the prior generation.

## Running this implementation

Register the route and its language variants in `Page_Mount.templates`. Each variant names a JSX source file, its browser module URL and a localized recovery label. Applications can bake catalog output into those sources before starting Saba. The route's `language` and `authorize` callbacks run before serving the selected document. They should fit the request worker's synchronous budget. Private record reads and potentially blocking storage use the application's async API. [Page build and response selection](../../src/pages/build.odin) · [Counter example](../SABA_UI_CONTEXT.md#write-and-serve-a-compiled-component)

A process prepares the active generation before accepting traffic. The generation is named by a digest of everything it serves: every linked module and every document, hashed with SHA-256 in a stable order and truncated to 16 bytes. Processes built from the same sources therefore advertise the same generation and can answer each other's module requests, and a restart with unchanged content keeps the URLs that browsers have already cached. Any change to a module or a document produces a new name.

Configure `archive_directory` on persistent storage to carry older modules through a production restart. Each build writes its own modules there, then loads the generations it finds. `archive_retention` bounds what is kept. A generation's retention period starts when a later build first finds it superseded, so a build that served for a month is still kept for the full period after its replacement starts. `max_age` defaults to seven days and `max_count` to eight superseded generations; a negative value removes that limit. `max_archive_bytes` bounds the archive file a build will read, at most and by default 64 MiB. Each build deletes archives past either limit, and staging files older than 15 minutes, which belong to a writer that died. A build reports and skips an archive it cannot use, such as a truncated, oversized or foreign file, and still starts. Only a directory it cannot create, list or write stops it. Archives are written to a staging file, synced and then renamed. Retained generations are compressed at a lower Brotli level than the active one, since they are recompressed on every start.

In development the watcher publishes only after a successful rebuild and keeps the immediately preceding generation in memory when no archive is configured. With an archive directory, a request for a generation the process does not hold looks for that generation's archive file there, so processes that share the directory, as during a rolling deployment, serve each other's builds, including builds written after they started. `archive_retention.rescan_interval` bounds how often each generation is looked for: zero selects two seconds and a negative value turns the lookup off after preparation. A generation found this way is read once, on the request's thread, with the limits and skip-and-warn rules of preparation; its age counts from retirement as above, and late loads stop at `max_count` (64 when the count is unlimited). Its files live until `release_build`, which the facade calls when it replaces or stops a build; an application that prepares pages itself calls it once no request can reach the build. Processes that do not share the archive directory still do not learn of each other's generations, so such a deployment must route its asset prefix to a process that holds an advertised generation for the retention period. A request for a generation a process neither holds nor finds returns 404 with `Cache-Control: no-store`. [Build archive](../../src/pages/build.odin) · [Development publication](../../src/application/application.odin) · [Browser recovery across four generations](../../tests/ui/delivery_test.odin)

Local component bodies that the compiler can prove safe can contribute static HTML. Imported, recursive or parser-sensitive subtrees can instead occupy browser-owned ranges. Browser rendering preserves their effective SVG or MathML namespace. Unsupported page definitions fail the opt-in template build with a diagnostic. Existing directory page mounts continue to use the append-style entry. [Template compiler](../../src/jsx/template.odin) · [Template acceptance fixture](../../testdata/ui_template/page.jsx)
